# MaixCAM2 红/蓝球 ROI 识别设计

## 目标

在 `licang_BLUE_RED_BALL.py` 中实现一个单文件、持续运行的 MaixCAM2 红/蓝球识别程序：启动后打开 B25 补光灯；默认红球模式；通过 UART 或触摸屏切换模式；只在配置的 ROI 中使用 `find_blobs` 识别当前颜色；可靠识别后向主控发送一次 ASCII `1`，目标消失后允许再次触发。

## 边界与硬件接口

- 只修改目标脚本，不改目录中的既有参考脚本。
- 使用 MaixCAM2 官方 UART4：TX=A21、RX=A22、设备 `/dev/ttyS4`，115200 8N1。
- UART 输入协议为 ASCII `1`/`2`，兼容 CR/LF；输出协议为 `b"1\\n"`。
- 使用 B25 作为板载照明 LED，GPIO 高电平开启，并在主循环期间保持开启。
- 使用 `touchscreen.TouchScreen()`；屏幕底部设置 RED、BLUE 两个点击区域。

## 状态与数据流

全局状态包括 `current_mode`、`detected_latched`、连续检测帧计数和连续丢失帧计数。所有 UART 和触摸输入都调用 `set_mode(mode, source)`，函数验证模式并清除识别锁。

主循环每帧按以下顺序执行：

1. 非阻塞读取 UART，逐字节处理 `1` 和 `2`，忽略 CR/LF 及其他字符。
2. 非阻塞读取触摸，判断 RED/BLUE 按钮并切换模式。
3. 读取一帧图像，按 `current_mode` 选择阈值。
4. 调用 `img.find_blobs([threshold], roi=ROI, pixels_threshold=..., area_threshold=..., merge=True)`。
5. 过滤面积、宽高、长宽比，多个候选选择面积最大者。
6. 连续确认达到阈值后发送一次 `b"1\\n"`；连续丢失达到阈值后解除锁存。
7. 绘制 ROI、目标框/中心点、模式和 SEARCHING/DETECTED 状态，然后显示图像。

## 配置

所有现场参数集中在文件顶部：相机分辨率、UART 参数、`ROI=[x,y,w,h]`、红蓝 LAB 阈值、像素/面积阈值、宽高范围、长宽比范围、确认/解除锁帧数和触摸按钮区域。红蓝阈值明确标注为需要在 B25 补光灯开启后的实机环境中重新标定。

## 错误处理与兼容性

MaixPy 模块只在目标板上使用；本地静态语法检查不依赖 MaixPy。UART、触摸和绘图的单次异常应被捕获并保持主循环继续运行。串口读取使用立即返回的轮询形式，禁止阻塞等待。

## 验证标准

- Python 语法检查通过。
- 可执行纯 Python 自测，覆盖模式切换、CR/LF 输入、识别锁、尺寸/比例过滤和 UART 输出节流。
- 静态检查确认所有 `find_blobs` 调用均传入 ROI，主循环持续执行视觉识别，且没有阻塞式 UART 读取。
- 上板后按需求逐项验证补光灯、红/蓝模式、触摸覆盖、UART 覆盖、ROI 限制、重复识别和重新下发任务。
